Permutation importance

Idea

In the OOB cases for a tree, randomly permute all values of the \(j\)th variable. Put these new covariate values down the tree and compute a new internal error rate. The amount by which this new error exceeds the original OOB error is defined as the importance of the \(j\)th variable for the tree. Averaging over the forest yields VIMP.

— Measure 1 (Manual On Setting Up, Using, And Understanding Random Forests V3.1

Learn more [1]: http://randomforestsrc.org/articles/vimp.html

OOB explanation

The tree OOB error rate is \[ \frac{1}{\# O_{ib}}\sum_{i\in O_{ib}} L(Y_i,h^*_b(\mathbf{x}_i)) \]

Permute (perturb) the \(j\) covariate feature for \(i\) to obtain \(\mathbf{x}^{*(j)}_i\)

The tree VIMP is therefore \[ \frac{1}{\# O_{ib}}\sum_{i\in O_{ib}} L(Y_i,h^*_b(\mathbf{x}^{*(j)}_i)) - \frac{1}{\# O_{ib}}\sum_{i\in O_{ib}} L(Y_i,h^*_b(\mathbf{x}_i)) \]

Averaging over trees gives VIMP. Large values identify important variables (negative values can occur!)

Confidence intervals for VIMP

VIMP standard error and CI are obtained using subsampling

Subsampling samples data without replacement where the subsample size \(m\) is substantially smaller than \(n\); eg: \[ m=\sqrt{n}=\sqrt{2231}\approx 48\ll n=2231 \]

CI are obtained using normal approximations \[ \texttt{vimp} \pm z_{\alpha/2} \hat{\sigma} \] where \(\hat{\sigma}\) is the subsampled standard error estimator[2, 3]

## example using peakVO2
data(peakVO2, package = "randomForestSRC")
o <- rfsrc(Surv(ttodead, died)~., peakVO2, importance="permute")
oo <- subsample(o)
plot.vimp.ci(oo, alpha=.05)

VarPro

VarPro works directly with the observed data creating a test statistic [5]

For each tree branch (a rule), the rule is released along the coordinate \(j\). Importance equals the difference between the test statistic for the original rule to the released rule

Variable Priority (VarPro)

``Rule-and-Release” Approach

VarPro provides a model-independent framework for measuring variable importance based on rule regions in the feature space

Key ideas:

  • Use rules derived from tree-based partitions
  • Measure local conditional mean sensitivity within each rule region
  • Aggregate rule-level contributions to obtain global importance scores

Data Setup

Assume a dataset \(\{(X_i, Y_i)\}_{i=1}^n\)

where

  • \(X_i = (X_{i1}, \ldots, X_{ip})\) are predictors
  • \(Y_i\) is the outcome

Goal: identify which variables drive the target functional

\[ \psi(\mathbf{X}) = \mathbb{E}[g(Y) \mid \mathbf{X}] \]

where \(g\) is chosen to reflect the scientific question (e.g., \(g(Y)=Y\) for regression, \(g(Y)=I\{Y=c\}\) for classification)

The true signal set \(\mathcal{S} \subseteq \{1,\ldots,p\}\) indexes variables that genuinely influence \(\psi(\mathbf{X})\); the complementary noise set is

\[ \mathcal{N} = \{1,\ldots,p\} \setminus \mathcal{S} \]

Goal: recover \(\mathcal{S}\) and screen out \(\mathcal{N}\)

Rule Regions

A rule \(\zeta\) specifies a local region of the feature space \(\mathcal{X}\):

\[ R(\zeta) \subseteq \mathcal{X} \]

Rules are obtained from tree paths (e.g., age \(> 50\) and tumor size \(< 2\) cm)

Local estimator within rule \(\zeta\):

\[ \hat{\theta}_n(\zeta) = \frac{1}{\#\{i \mid \mathbf{X}_i \in R(\zeta)\}} \sum_{i:\,\mathbf{X}_i \in R(\zeta)} g(Y_i) \]

Local Variable Sensitivity

To test whether \(X^{(j)}\) matters, release it from rule \(\zeta\) by setting \(S = \{j\}\):

\[ R(\zeta^{(S)}) = \bigl\{\mathbf{x} \in \mathcal{X} \mid \mathbf{x}^{\setminus(S)} \in R(\zeta)\bigr\} \]

with local estimator \(\hat{\theta}_n(\zeta^{(S)}) = \frac{1}{\#\{i \mid \mathbf{X}_i \in R(\zeta^{(S)})\}} \sum_{i \mid \mathbf{X}_i \in R(\zeta^{(S)})} g(Y_i)\)

The local importance score compares averages before and after releasing:

\[ \bigl|\hat{\theta}_n(\zeta^{(S)}) - \hat{\theta}_n(\zeta)\bigr| \]

  • Large difference → \(X^{(j)}\) strongly influences predictions in this region
  • Near zero → \(X^{(j)}\) is locally irrelevant (noise behavior)

Aggregating Across Rules

Aggregate the local scores over \(K_n\) rules with weights \(W_{n,k}\) proportional to rule support:

\[ \Delta_n(S) = \sum_{k=1}^{K_n} W_{n,k} \, \bigl|\hat{\theta}_n(\zeta_{n,k}^{(S)}) - \hat{\theta}_n(\zeta_{n,k})\bigr| \]

  • \(\Delta_n(\{j\})\) measures global variable priority for \(X^{(j)}\), where set \(S = \{j\}\)
  • Weights \(W_{n,k} = m_{n,k} / \sum_j m_{n,j}\) prioritize rules with more observations

Algorithm Outline

Repeat for \(b = 1, \ldots, B\):

  1. Split data \(\mathcal{D}\) into rule-generation set \(\mathcal{D}^b_\text{rg}\) (\(63.2\%\)) and scoring set \(\mathcal{D}^b_\text{vp}\) (\(36.8\%\))
  2. Generate rules from \(\mathcal{D}^b_\text{rg}\) using randomized trees with guided feature sampling (weights from lasso + shallow-tree split frequencies)
  3. Score each variable \(X^{(s)}\) on \(\mathcal{D}^b_\text{vp}\): compute \(\Delta_n^b(s)\) by aggregating \(|\hat{\theta}_n(\zeta_{n,k}^{(s)}) - \hat{\theta}_n(\zeta_{n,k})|\) over \(K_n\) rules

After \(B\) replications, compute the standardized importance score:

\[ I_{n,B}(X^{(s)}) = \frac{\bar{\Delta}_n(s)}{\sqrt{\widehat{\mathrm{Var}}_n(s)}} \]

Declare \(X^{(s)}\) a signal if \(I_{n,B}(X^{(s)}) > Z_0\) (e.g. \(Z_0 = 2\), or chosen by out-of-sample validation)

VarPro: pros and cons

Pros:

  1. Much faster
  2. Much better for correlated problems
  3. User specified test statistics
  4. Doesn’t depend on prediction error
  5. Tree guided rules can be specified by the user
  6. Sparsity property

Cons:

  1. Importance value does not have an intuitive interpretation

iVarPro: Why care about individual importance?

  • Average (global) importance can miss heterogeneity
    e.g. \(y_i = \beta_0 + \beta_1 x_{i1} + \beta_2 x_{i2} + \dots + \beta_p x_{ip} + \varepsilon_i\)
  • Precision decisions need patient-specific drivers
  • We want sensitivity: “how much does a tiny nudge in \(x^{(s)}\) change my outcome?”

From population to individual

  • Population: “What matters on average?” (Breiman’s permutation importance)
  • Individual: “What matters for this case?”

Let \(\def\grad{{ \nabla}}\def\x{{\bf x}}\def\xs#1{x^{(#1)}}\psi(\x) = \mathbb{E}(\phi(Y) | \x)\) be the unknown target function for the feature vector \(\x = (\xs{1}, \ldots, \xs{p})^T\), where \(Y\) is the outcome and the choice of \(\phi\) depends on the specific problem

iVarPro defines individual importance as the local gradient [7]: \[ \grad \psi(\x) = \left(\frac{\partial \psi(\x)}{\partial \xs{1}}, \ldots, \frac{\partial \psi(\x)}{\partial \xs{p}}\right)^T := \left(g^{(1)}(\x), \ldots, g^{(p)}(\x)\right)^T \] The values \(g^{(s)}(\x)\) represent the individual variable importance for features \(\xs{s}, s = 1, \ldots, p\)

Intuition: gradient = sensitivity to small changes in \(x^{(s)}\) at this \(\x\)

  • Use tree rules to define a local region \(R\) around a point
  • Release the constraint on one variable \(x^{(s)}\) to get variation only along that axis

Variable Priority (VarPro) rules

Core idea in one picture

  • Use tree rules (VarPro) to define a local region \(R\) around a point
  • Release the constraint on one variable \(x^{(s)}\) to get variation only along that axis
  • Fit a tiny local linear regression to get the slope = gradient
  • Average over many rules to obtain individual variable priority (iVarPro) score

Why not just SHAP or LIME?

  • SHAP (Shapley Additive Explanations) or LIME (Local Interpretable Model-Agnostic Explanations) depend on the fitted model and a background distribution
  • Perturbations can create unrealistic points
  • iVarPro stays model-independent, uses observed data only, and targets directional derivatives directly

Working theory: when the surface \(\psi(x)\) is smooth locally, these tiny local regressions recover gradients well

iVarPro: using rules to obtain local gradients

The importance of a variable \(s \in \{1, \ldots, p\}\) is assessed by comparing estimates within a rule’s region \(R\) to those in its corresponding release region, defined as the region \(R\) expanded where constraints on \(\xs{s}\) are removed [varpro2024?]

Let \(\x_0 := \x_0(R)\) denote the centroid of \(R\), and assign its gradient to all cases in \(R\). To define the gradient at \(\x_0 = (x_0^{(1)},\ldots,x_0^{(p)})^T\) along coordinate \(s\), let \(\psi_R^{(s)}(z)\) represent the evaluation of \(\psi\) at \(\x_0\), with the \(s\)-th coordinate perturbed by an increment \(z\): \[ \psi_R^{(s)}(z) = \psi(x_0^{(1)},\ldots,x_0^{(s-1)},x_0^{(s)}+z,x_0^{(s+1)},\ldots,x_0^{(p)}) \] By construction, \(\psi_R^{(s)}(0) = \psi(\x_0)\), and the gradient of \(\psi\) at \(\x_0\) along coordinate \(s\) is formally given by \[ g_R^{(s)} := g_R^{(s)}(\x_0) =\lim_{z\rightarrow 0} \frac{\psi_R^{(s)}(z)-\psi_R^{(s)}(0)}{z} \]

Gradient estimation via local linear regression

To estimate the gradient, we employ a local linear regression model. In small regions around \(\x_0(R)\) along the coordinate direction \(s\), we approximate \(\psi\) using the linear model: \[ \psi_R^{(s)}(z) = \psi_R^{(s)}(0) + z g_R^{(s)} \] Given training data \((\x_1, y_1),\ldots,(\x_n, y_n)\), we regress \(\{y_i\}\) on the \(s\)-coordinate features \(\{x_i^{(s)}\}\) using an intercept-slope model based on data local to \(R\). The gradient \(g_R^{(s)}\) is estimated using the least squares estimate of the slope

Standardized covariates

To systematically control the extent of this expansion, we introduce an index \(\scriptsize \def\l{\lambda} \def\psihat{\widehat{\psi}} \def\ghat{\widehat{g}} \def\bhat{\widehat{\beta}} 0 \le \l \le \l_0\) that determines the proportion of individuals selected from the release region \(\scriptsize R^{(s)}\). Larger values of \(\scriptsize \l\) correspond to a greater number of included individuals. The expanded region is then defined as \(\scriptsize R(s,\l) = R \cup R_\l^{(s)}\), where \(\scriptsize R_\l^{(s)}\) is a restricted subset of \(\scriptsize R^{(s)}\) determined by \(\scriptsize \l\)

we center \(\scriptsize x_i^{(s)}\) at the centroid value \(\scriptsize x_0^{(s)}(R)\) and then scale it to have unit length, denoting the transformed values by \(\scriptsize z_i^{(s)}\):

\[ \scriptsize z_i^{(s)} = \frac{x_i^{(s)} - x_0^{(s)}(R)} {\sqrt{\displaystyle\sum_{\x_j\in R(s,\lambda)}(x_j^{(s)} - x_0^{(s)}(R))^2}} %\quad \x_i\in R(s,\lambda) \]

The local gradient is estimated via least squares regression using the data \(\scriptsize \{z_i^{(s)},\psihat(\x_i)\}\) within \(\scriptsize R(s,\lambda)\): \[ \scriptsize \psihat(\x_i) = \alpha_R^{(s)} + z_i^{(s)} \beta_R^{(s)} + \varepsilon_i, \quad \x_i \in R(s,\lambda) \] The least-squares slope is then used as the local gradient estimate: \(\scriptsize \ghat_R^{(s)}:=\bhat_R^{(s)}\)

Cross-Validation for optimizing the fit

For a given \(\scriptsize \def\l{\lambda} \def\fhat{\widehat{f}} \l\), the Predicted Residual Sum of Squares (PRESS) statistic is computed as follows. The leave-one-out (LOO) residual for observation \(\scriptsize i\) is: \[ {\tiny e_i = \psihat(\x_i) - \fhat^{(-i)}(z_i^{(s)}), } \] where \(\scriptsize \fhat^{(-i)}(z_i^{(s)})\) is the least squares predicted value at \(\scriptsize z_i^{(s)}\) when the \(\scriptsize i\)-th observation is excluded from the regression fit. The PRESS statistic is then given by: \[ {\tiny \text{PRESS}(s,\l) = \frac{1}{|R(s,\l)|} \sum_{i\in R(s,\l)} e_i^2 } \] Since local regression follows a linear model, the PRESS statistic simplifies in terms of leverage values \(\scriptsize h_i\): \(\scriptsize e_i = \frac{\psihat(\x_i) - \fhat(z_i^{(s)})}{1 - h_i},\) where \(\scriptsize h_i\) is the leverage for \(\scriptsize z_i^{(s)}\) and \(\scriptsize \fhat\) is the least squares predictor. Thus, the PRESS statistic can be rewritten as: \[{\tiny \text{PRESS}(s,\l) = \frac{1}{|R(s,\l)|} \sum_{i\in R(s,\l)} \left( \frac{\psihat(\x_i) - \fhat(z_i^{(s)})}{1 - h_i} \right)^2 } \] The optimal \(\scriptsize \l^*=\text{argmin}_\l \text{PRESS}(s,\l)\) is selected

iVarPro pipeline

  1. Build VarPro rules (randomized trees)
    → small rectangular regions \(R\)
  2. For each feature \(s\) and rule \(R\):
    • Release \(x^{(s)}\) to form \(R^{(s)}(\lambda)\)
    • Standardize \(x^{(s)}\) around the region centroid
    • Regress \(\widehat{\psi}(x)\) on standardized \(x^{(s)}\), choose \(\lambda\) by PRESS (LOO)
    • Slope \(\Rightarrow \widehat{g}^{(s)}_R\)
  3. For case \(x_i\): average \(\widehat{g}^{(s)}_R\) over all rules containing \(x_i\)

Tip: \(\widehat{\psi}\) from RF/GBM/XGBoost smooths noise → better local slopes

Overview of the varPro Package

(A) Random forest grows trees with terminal-node rules → (B) Four-step rule-and-release ensemble: Grow · Extract · Compute statistic · Aggregate → (C–F) Analysis modes: Supervised VarPro · Unsupervised UVarPro · Individual iVarPro · OOD (out-of-distribution) detection outPro

Rule-and-Release: The Core Idea

Unified algorithm — 5 steps:

  1. Grow a forest, extract terminal-node rules \(\{\zeta_k\}\)
  2. Release each rule by dropping constraints on variable \(s\)
  3. Compute problem-specific statistic \(T_{k,s}\) from \(R_k\) and \(R_k^{(s)}\)
  4. Aggregate \(\{T_{k,s}\}\) across rules and trees
  5. Return structured objects for downstream analysis

Four analysis modes — same algorithm, different \(T_{k,s}\):

Mode Statistic
VarPro Conditional mean contrast
UVarPro \(\ell_1\)-logistic models
iVarPro Local gradient (slope)
outPro Subspace distance

No synthetic covariates, no permutations — all contrasts use observed data only.

Summary

What varPro delivers

  • Unified interface — one package for supervised, unsupervised, and individual-level importance via consistent S3 generics

  • Observed-data only — no permutations, no synthetic covariates; rule/release contrasts use the original data

  • Four analysis modes each built on the same rule-and-release core:

    • varpro() / cv.varpro() — global screening
    • uvarpro() — unsupervised feature selection
    • ivarpro() — case-specific interpretation
    • outpro() / isopro() — deployment diagnostics

  • Scalable — parallel execution, interfaces with randomForestSRC
